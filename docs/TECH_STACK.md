# Tech stack

- `backend/`: FastAPI and SQLAlchemy Core, on Supabase's Postgres when `DATABASE_URL` is set (all its tables in the `undercover` schema, at most 4 connections) and on SQLite otherwise, which is what the tests use. Every API operation has an `operation_id`, a one-line docstring and no optional inputs. Paying a claim is a separate operation that takes the amount. It holds the runs, their to-do lists and every attempt on a claim with the agent's thread for it, and it enforces a run's limit and the retry rules. It applies UnderCover's payout rules in `calculate_payout`, and it tells the agent whether a payout needs a sign-off.
- `agent/`: LangChain and LangGraph on OpenRouter, with no other agent framework. The queue agent, on LangChain's `create_agent`, works a run: it plans a to-do list, hands each claim to a claim agent and finishes with a summary. The claim agent is a hand-written LangGraph graph with its own state, nodes and edges, for each claim: the model and its tools, a check of the claim, an approval that waits for a handler's sign-off with `interrupt()`, and the payment. It saves its progress after every step in the same Supabase database with LangGraph's synchronous Postgres checkpointer (`durability="sync"`), so a stopped claim carries on from where it got to. Both agents reach claims, documents and their instructions only through the backend's API, and the claim agent looks up the policy wording and the claims manual by section. Its parts are the queue agent (`queue.py`), the claim agent (`main.py`), the command line (`__main__.py`) and the agent's service (`service.py`), a small web service that works a claim on a thread and which the backend calls, on `UNDERCOVER_AGENT` (default http://127.0.0.1:8002). Every claim's work is traced in Langfuse as one session. Entry points: `run_queue(run_id)` for a run and `run(claim_id, thread_id)` for one claim. They use `deepseek/deepseek-v4.1-flash` with low reasoning effort by default, or the model in the environment variable `MODEL_NAME` if set, such as `openrouter/free`.
- `dashboard/`: React, Vite and TypeScript. Its API types are generated from the backend's OpenAPI document with `npm run types`.
- `e2e/`: Playwright tests.
- `data/`: the business data the backend starts from. The agent never sees `data/evals/`, which holds the answer key.

Python 3.12 with uv, all in the root `pyproject.toml`. Node 26. The keys and the database are in `.env`: `OPENROUTER_API_KEY`, `DATABASE_URL` (Supabase's session pooler), and the Langfuse keys `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` and `LANGFUSE_BASE_URL`.
