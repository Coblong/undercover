# Tech stack

- `backend/`: FastAPI and SQLAlchemy Core, on Supabase's Postgres when `DATABASE_URL` is set (all its tables in the `undercover` schema, at most 4 connections, which a request waits a minute for) and on SQLite otherwise, which is what the tests use. Every API operation has an `operation_id`, a one-line docstring and no optional inputs (a value that is sometimes absent is a required field that may be null). Paying a claim is a separate operation that takes the amount. It holds the dispatches and evaluations and the claims each works, every attempt on a claim with the agent's thread for it, the tokens, cost and working time of every claim, and the answer key (the handlers' decisions on both labelled sets, apart from every claim operation); it enforces the retry rules, and it scores each evaluation from its own records. It applies UnderCover's payout rules in `calculate_payout`, and it tells the agent whether a payout needs a sign-off.
- `agent/`: LangChain and LangGraph (1.2.19 or later, for a node's `error_handler`) on OpenRouter, with no other agent framework. The dispatcher (`dispatcher.py`) is a LangGraph graph with no model: it lists a run's claims, fans out one `Send` for each, with `max_concurrency` set to N, and works the claims that went back to the queue once more. Its worker retries a rate limit or a timeout (LangChain's `ModelRateLimitError` and `ModelTimeoutError`) and leaves a claim in progress when the retries run out. The claim agent is a hand-written LangGraph graph with its own state, nodes and edges, for each claim: the model and its tools, a check of the claim, an approval that waits for a handler's sign-off with `interrupt()`, and the payment. It saves its progress after every step in the same Supabase database with LangGraph's synchronous Postgres checkpointer (`durability="sync"`), each claim agent on a saver of its own over one shared pool of at most 4 connections, so a stopped claim carries on from where it got to. The agent reaches claims, documents and its instructions only through the backend's API, and looks up the policy wording and the claims manual by section. Its parts are the claim agent (`main.py`), the dispatcher (`dispatcher.py`), the command line (`__main__.py`) and the agent's service (`service.py`), a small web service that works a claim on a thread and starts dispatches and evaluations, which the backend calls on `UNDERCOVER_AGENT` (default http://127.0.0.1:8002). Every claim's work is traced in Langfuse as one session, and a claim worked for a run has its trace tagged `run-<id>`. Entry points: `work_claim(claim_id, run_id, new_saver)`, the one function the dispatcher calls, and `run(claim_id, thread_id)` for one claim. They use `openai/gpt-6-luna` with low reasoning effort by default, or the model in the environment variable `MODEL_NAME` if set, such as `openrouter/free`, which runs with no reasoning effort. Cost is OpenRouter's `usage.cost` on each reply, and on a key of our own (`is_byok`) the provider's charge in `cost_details` is added, since OpenRouter's own fee is all `cost` holds then.
- `dashboard/`: React, Vite and TypeScript. Its API types are generated from the backend's OpenAPI document with `npm run types`.
- `e2e/`: Playwright tests.
- `data/`: the business data the backend starts from. The agent never sees `data/evals/`, which holds the answer key.

Python 3.12 with uv, all in the root `pyproject.toml`. Node 26. The keys and the database are in `.env`: `OPENROUTER_API_KEY`, `DATABASE_URL` (Supabase's session pooler), and the Langfuse keys `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` and `LANGFUSE_BASE_URL`.
